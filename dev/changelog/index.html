    IntGenomicsLab/lrsomatic: Changelog¶

    The format is based on Keep a Changelog and this project adheres to Semantic Versioning.

    v1.2.0dev¶

    Added¶

    • #268 - The documentation site (https://intgenomicslab.github.io/lrsomatic/) is now versioned with mike and built by the Docs workflow: /latest/ follows the newest GitHub release, every release keeps its own /<version>/, and /dev/ tracks the dev branch. The MkDocs sources (mkdocs.yml, schema_render.py, docs/) are now in the repository.
    • #258 - LRSOMATICREPORT passes the run mode to the report, --run-mode paired when meta.paired_data is set and --run-mode tumour_only otherwise, instead of the report inferring it from whether normal-side QC files were staged (campaign E-F2: a pair run without mosdepth, cramino and samtools stats was badged tumour-only and given the tumour-only caveat). Requires lrsomatic_report >= 2.1.0, which this release pins. The stub writes the flag into its HTML, and the stub pipeline test checks it per sample (@ljwharbers).
    • #258 - LRSOMATICREPORT is now also given variants/clairsto/<sample>.verdict_status.tsv (tumour-only) and ReConPlot's --reconplot_regions figures, reconplot/<pair>/focus/*.png, which were published but never staged (RECONPLOT_FIGURES gains a focus emit). Report 2.1.0 renders them as the tumour-only Verdict warning and the "Your regions" block that opens the ReConPlot section. The stub pipeline test now runs with --reconplot_regions and checks both relpaths, and a real-render module test stages both files and checks that the report shows both (@ljwharbers).
    • #258 - Tumour-only samples get variants/clairsto/<sample>.verdict_status.tsv, saying whether ClairS-TO's Verdict tagged the calls (applied), ran and tagged nothing (skipped: purity above 0.6, or no purity/ploidy solution) or did not run (not_run), with the purity, ploidy and purity source it used (ascat from CLAIRSTO_VERDICT_TAG, clairsto_internal with --skip_ascat) and Verdict's own reason. Until now a skip was only visible in the task's .command.out, although it leaves somatic.vcf.gz mostly germline on a high-purity tumour (73-93 % of PASS SNVs at VAF >= 0.35 on three 30x samples with ASCAT purity 0.66-0.82). The pipeline log now warns for every skipped or not_run sample, naming it with its purity and source. CLAIRSTO_VERDICT_TAG takes the status from whether Verdict wrote tagged VCFs (it writes them only when it tags); CLAIRSTO from Verdict's tagging logs, which exist only when Verdict ran and carry its skip message. New bin/verdict_status.py, verdictStatusWarning() and tests for both paths (@ljwharbers).
    • #243 - LRSOMATICREPORT stages every other output the report reads through one generic input, two parallel lists extra_relpaths/extra_files: each file is linked at its published path under the tool's sample directory (<outdir>/<sample>/ layout), so a new report input needs no new module slot. The report now also receives SigProfiler activities, fit statistics and matrices, ShatterSeek summaries, the ecDNA outputs (AmpliconClassifier profiles, gene list and result table, the CoRAL seeds, amplicon summary and graph/cycles PNGs), SAVANA's somatic SV VCF (PoN-filtered for PacBio tumour-only), fitted purity/ploidy and VEP annotation, Padfoot's per-pair tables, ReConPlot's PNG figures, Wakhan's top-ranked integer_profile.bed and gene copy-number states, and ASCAT's metrics.txt. Each file stages in its own numbered directory, so per-pair files sharing a base name (Padfoot's by_gene.tsv, ReConPlot's figures) do not collide (@ljwharbers).
    • #243 - LRSOMATICREPORT publishes <sample>_small_variants.tsv.gz beside the HTML: the full small-variant table, written when the somatic VEP file holds at least one variant. The report tool's new --embed slim|full (which rows the HTML table embeds; default slim) has no pipeline parameter and is passed through ext.args (@ljwharbers).
    • #243 - New emits for the report: SIGPROFILER_ASSIGNMENT.out.solution_stats (Assignment_Solution/Solution_Stats/*_Samples_Stats.txt), ECDNA.out.{gene_list,result_table,seeds,summary}, PADFOOT_ANNOTATION.out.{annotated_svs,by_gene} and RECONPLOT_FIGURES.out.{genome_wide,per_chromosome}, with assertions in their stub tests, and LRSOMATICREPORT stub tests that same-named files land at their own paths and that mismatched lists fail (@ljwharbers).
    • #222 - Added ShatterSeek chromothripsis calling for every CN/SV caller pair with output for a sample (ASCAT + Severus, Wakhan + Severus, SAVANA), published to <sample>/shatterseek/<pair>/ with a per-chromosome summary, the exact ShatterSeek inputs and a figure per called chromosome; each cluster is labelled with the PCAWG high-confidence tiers (HC1, HC2, HC3; Cortes-Ciriano et al. 2020, ShatterSeek issue #22), with BH q-values at 0.2 and cut-offs overridable through ext.args. The pipeline runs upstream parklab/ShatterSeek with a build-time patch adding T2T-CHM13, inside docker.io/robertaforsyth/shatterseek (SIF twin oras://docker.io/robertaforsyth/shatterseek-sif, recipe in containers/shatterseek/); the callers are read by the ReConPlot wrapper's parsers. --skip_shatterseek, --shatterseek_genome and --shatterseek_min_svlen (intra-chromosomal SVs shorter than 150 bp are left out by default) control it (@robert-a-forsyth).
    • #221 - SigProfilerAssignment now also exports the probability of each COSMIC signature for every somatic mutation (Assignment_Solution/Activities/Decomposed_Mutation_Probabilities/), e.g. to attribute a driver mutation to a signature (@robert-a-forsyth).
    • #221 - Added non-stub SIGPROFILER_ASSIGNMENT nf-tests (tag small) that fit synthetic SBS96, DBS78 and ID83 matrices on GRCh38 and CHM13-T2T and check the per-mutation probabilities of every context (@robert-a-forsyth).
    • #204 - Added haplotype differential methylation region (DMR) calling: with --modkit_phased set, modkit dmr pair compares methylation between the _hp1/_hp2 bedMethyl pileups over CpG islands covered in both haplotypes, and each DMR call is annotated with its nearest gene via bedtools closest. Runs automatically whenever --modkit_phased is set; turn it off with --skip_dmr. --dmr_cpg_islands_bed/--dmr_gencode_gene_bed have built-in defaults for --genome GRCh38/CHM13 and must be supplied explicitly for any other genome, or DMR is skipped with a warning rather than failing the run. Tumour/normal (cross-sample) DMR is explicitly out of scope for this PR (@YannVRB).
    • #204 - Added a real, public subworkflow-level nf-test for the DMR subworkflow (tag small), chaining MODKIT_PILEUP on the public phased, methylation-tagged test.sorted.phased.bam fixture through the full DMR chain against a small synthetic CpG-island/gene region (@YannVRB).
    • #205 - Added ecDNA and focal amplification analysis: CoRAL reconstructs amplicon structures from each tumour BAM, seeded by ASCAT's copy-number calls, and AmpliconClassifier labels each amplicon as ecDNA, BFB or linear. Runs by default on tumour samples with ASCAT calls; turn it off with --skip_coral, or keep reconstruction without classification with --skip_ampliconclassifier. CoRAL's optimisation defaults to the open-source SCIP solver rather than Gurobi: across the 1102 solver logs from the previous standalone cohort the largest model was 620 rows by 438 columns and the slowest solve took 0.49 s, so a licensed solver buys nothing at this scale, though --coral_solver gurobi_direct with --gurobi_license remains available. AmpliconClassifier's AmpliconArchitect data repository is downloaded automatically for GRCh38, checked against a pinned --aa_data_repo_md5, and can be supplied with --aa_data_repo (the reference directory or its parent); CHM13 has no published repository, so without --aa_data_repo the classifier is skipped with a warning (@robert-a-forsyth).
    • #205 - Added ascat_to_coral_bed.py and the ASCAT_TO_CORAL_BED module, converting ASCAT's cnvs.txt into the headerless BED CoRAL seeds from. Contigs are respelled to match the reference, since ASCAT writes 1 where the BAM may say chr1 and CoRAL builds its chromosome sizes from the BAM header; zero-length and inverted segments are dropped, which CoRAL's own parser would otherwise reject (@robert-a-forsyth).
    • #205 - Added stub nf-tests for the ECDNA subworkflow and ASCAT_TO_CORAL_BED (tag small), covering the seeded path, the empty-seed branch, the opt-in cycle re-extraction with plotting, the --skip_ampliconclassifier path and a run with no data repository, plus a stub test for AADATAREPO_DOWNLOAD (@robert-a-forsyth).
    • #207 - The samplesheet now accepts CRAM as well as BAM (.cram in bam_tumor/bam_normal), unaligned or aligned to any assembly. An aligned CRAM is decoded with --fasta only when no contig name has a different M5 checksum in the two (checked in METAEXTRACT for CRAMINO_PRE, and inside MINIMAP2_ALIGN), otherwise from its embedded reference, UR: path or REF_PATH: given a mismatched reference, htslib decodes an embedded-reference CRAM to wrong bases (63 of 1469 test reads) and exits 0. A run resumed from an earlier version re-runs METAEXTRACT, CRAMINO_PRE, CRAMINO_POST and MINIMAP2_ALIGN for BAM input too: Nextflow hashes the script source, and this PR edits all four (CRAMINO gained a --reference argument and a FASTA input) (@ljwharbers).
    • #207 - Aligned CRAM is accepted for samples that fibertools-rs reads (a fiber = y row, or PacBio reads with kinetics while m6A prediction runs). fibertools-rs takes no reference, so aligned input of these samples, BAM or CRAM, first goes through SAMTOOLS_VIEW_FIBERPREP (nf-core samtools/view, samtools 1.25), which keeps the primary records as BAM and decodes a CRAM with --fasta when its M5s match, otherwise from its embedded reference, UR: path or REF_PATH; a CRAM with none of those fails there with htslib's error. On Revio and ONT fiber-seq reads aligned to GRCh38, an embedded-reference CRAM 3.0 or 3.1 gave the same predict-m6a, add-nucleosomes, fire and qc output as the BAM. METAEXTRACT emits aligned_input ('true' for a BAM or CRAM with @SQ lines) for the decision. The step runs inside the FIBERSEQ subworkflow, where the rest of the samples reach fibertools-rs as given (@ljwharbers).
    • #207 - Added tests for CRAM input (tag small): module tests of METAEXTRACT and MINIMAP2_ALIGN on CRAMs built from a test BAM (aligned with and without the reference embedded, and unaligned), against a matching and a mismatched FASTA, which check the M5 decisions and that every CRAM realigns to the same records as the BAM; a module test of SAMTOOLS_VIEW_FIBERPREP's filter on that BAM with secondary alignments added, as BAM and as both CRAMs; -stub pipeline tests with BAM and CRAM rows mixed in one samplesheet and with fiber-seq rows given as aligned CRAM, aligned BAM and unaligned CRAM; and a function test of the fibertools-rs input selection (@ljwharbers).
    • #207 - Added a -stub pipeline test of --aligned_format cram and bam on the extended samplesheet (tag small), which checks the replicate merge and the published bamfiles/, and a read-group check in the default test. The pipeline could not run with -stub before: the METAEXTRACT stub reported no basecalling model, and the patched LONGPHASE_PHASE stub indexed VCFs it never wrote (@ljwharbers).
    • #215 - Added optional whitelist SV calling: SEVERUS now runs a patched Severus 1.7 image (oras://docker.io/amberverhasselt/severus-sif:1.7-whitelist-6813dee), whose output without a whitelist is identical to stock 1.7, and takes an optional whitelist BED: --severus_whitelist <bed> reports every SV inside the whitelisted regions, past the read-quality, minimum-support and VNTR filters, with corroboration required for single-read junctions. Extra flags go through --severus_whitelist_args. --severus_whitelist is not supported under Conda (@AmberVerhasselt).
    • #197 - Added CHM13 support for ClairS-TO's Verdict module, which tags tumour-only calls as germline, somatic or subclonal somatic; its resources were GRCh38-only, so on CHM13 germline variants leaked into somatic.vcf.gz. With --genome CHM13 --skip_ascat the pipeline builds a CHM13 resource set from the ASCAT files it already downloads and passes it as --cna_resource_dir; a prepared directory can be given with --clairsto_cna_resources (validated at launch). Without --skip_ascat tagging comes from ASCAT's own tables instead (next entry) (@ljwharbers).
    • #197 - Added CLAIRSTO_VERDICT_TAG: when ASCAT is in the run, Verdict's germline tagging is computed from ASCAT's purity, ploidy and segments instead of Verdict's own estimate, so CLAIRSTO runs with --disable_verdict and ASCAT runs before small variant calling. Output names are unchanged. The tables the tags were computed from are published as <sample>_Tumor_Purity_Ploidy.txt and <sample>_Tumor_CNA.txt, also on --skip_ascat runs (@ljwharbers).
    • #197 - Added a stub nf-test for TUMORONLY_SMALLVAR covering both germline tagging paths (tag small) (@ljwharbers).
    • #190 - Added mutational signature analysis: SigProfilerMatrixGenerator matrices (SBS/DBS/ID) and per-sample COSMIC signature fitting with SigProfilerAssignment on the phased somatic VCF, with CHM13-T2T support via a purpose-built image (ghcr.io/ljwharbers/sigprofiler) and CHM13-renormalised COSMIC signatures; new --sigprofiler_* / --download_sigprofiler_genome / --skip_signatures parameters (@ljwharbers).
    • #188 - Added modkit_args (default --cpg --modified-bases 5mC) to control the arguments passed to modkit pileup, and modkit_phased to run the pileup with --phased on the Longphase-haplotagged BAMs, producing _hp1, _hp2 and _combined bedMethyl files per sample (@ljwharbers).
    • #176 - Added LRSOMATICREPORT as the final pipeline step: a self-contained per-sample HTML report covering small variants, structural variants, copy number and QC. Skip it with --skip_report; choose the gene panel selected on load with --report_gene_panel (@ljwharbers).
    • #176 - Added the lrsomatic_report tool to the pipeline, first vendored as source at assets/lrsomatic_report, now shipped as a container (see the entry below) (@ljwharbers).
    • #176 - Added a solution_dirs output to the WAKHAN module so its per-solution copy-number plots can be staged downstream (@ljwharbers).
    • #193 - Added VEP plugins: AlphaMissense, SIFT/PolyPhen, ClinVar and REVEL on GRCh38, and AlphaMissense plus SIFT/PolyPhen on CHM13 via protein-space lookup. Enabled by default with --genome GRCh38 or --genome CHM13 (a first GRCh38 run downloads around 1.4 GB); any --vep_* path overrides its default and --skip_vep_plugins turns the set off. CADD and EVE are opt-in behind --vep_cadd_snv/--vep_cadd_indel and --vep_eve because of their size (81 GB and 9.6 GB); prepared REVEL and EVE files are published to <outdir>/vep_plugins/ for reuse. Two lab-hosted AlphaMissense files are CC BY 4.0 with attribution in CITATIONS.md (@AmberVerhasselt).
    • #189 - Added SAVANA structural variant and copy-number calling, running alongside Severus/ASCAT (@yannvrb).
    • #202 - Added Padfoot annotation of somatic SVs and CNAs for every caller pair with output for a sample, Severus + Wakhan and SAVANA, paired and tumour-only, published to <sample>/padfoot/<pair>/. Padfoot (a pinned commit of Tim-Yu/Padfoot, which adds SAVANA input) ships inside docker.io/timmy9527/padfoot-repeatmasker (oras://docker.io/timmy9527/padfoot-repeatmasker-sif under Singularity/Apptainer) with RepeatMasker on by default, so nothing is downloaded at run time and the module needs a container engine; gene copy number is labelled against the caller's fitted ploidy; --skip_padfoot and the --padfoot_* parameters control it (@Tim-Yu).
    • #202 - Added ReConPlot rearrangement and copy-number figures per CN/SV caller pair, reconplot/{severus_ascat,severus_wakhan,savana}/, with per-chromosome, genome-wide and optional focus panels plus the harmonised CN/SV tables. The wrapper ships in assets/reconplot/ and the ReConPlot R package inside docker.io/timmy9527/reconplot (oras://docker.io/timmy9527/reconplot-sif under Singularity/Apptainer; the image patches the package's genome-wide chromosome clipping), so nothing is downloaded at run time and the module needs a container engine; --skip_reconplot and the --reconplot_* parameters control it (@Tim-Yu).
    • #202 - PAIRED_SAVANA and TUMORONLY_SAVANA also emit the fitted purity/ploidy and the het-SNP allele counts, so Padfoot and ReConPlot can consume SAVANA output; ReConPlot reads SAVANA's SVs from the classified somatic VCF, since SAVANA writes no somatic BEDPE for PacBio (--pb) (@Tim-Yu).
    • #202 - Added stub nf-tests for PADFOOT_ANNOTATION and RECONPLOT_FIGURES that check every caller pair is formed (including ASCAT + Severus for tumour-only samples), unfitted samples are dropped and each task receives the top-ranked Wakhan solution's files (tag small) (@Tim-Yu).

    Changed¶

    • #261 - LRSOMATICREPORT runs lrsomatic_report 2.2.0 (ghcr.io/ljwharbers/lrsomatic-report:2.2.0 / oras://ghcr.io/ljwharbers/lrsomatic-report-sif:2.2.0). Changes since 2.1.0: the ecDNA "N more CoRAL plots not embedded" note names the folder relative to the sample directory instead of an absolute work-directory path; the overview shows a warning box when the purity estimates of ASCAT, Wakhan and SAVANA differ by 0.2 or more; the full small-variant table (<sample-id>_small_variants.tsv.gz) is now also embedded in the HTML, with Download and Show all controls, unless it is larger than 5 MB gzipped, so each report grows by about 4/3 of that file's size (@ljwharbers).
    • #260 - A fiber-seq file whose reads carry no m6A calls now skips the fibertools-rs nucleosome, FIRE and QC steps (and SAMTOOLS_VIEW_FIBERPREP) whenever the run predicts no m6A for it, not only under --skip_m6a: ONT reads basecalled without a 6mA model, and PacBio reads without kinetics. PacBio reads with kinetics still get m6A predicted and then the fiber steps unless --skip_m6a is set, and a file whose m6a_calls is 'unknown' keeps them. The rule shares one helper with the FIBERTOOLSRS_PREDICTM6A branch (m6aPredicted), and the warning names the reason for each skipped file. The fiber-seq -stub tests give their fixtures m6A calls so they still reach the fiber steps (@ljwharbers).
    • #258 - --genome GRCh38 now aligns to the NCBI no-ALT analysis set (GCA_000001405.15_GRCh38_no_alt_analysis_set, staged from its byte-identical iGenomes copy Homo_sapiens/NCBI/GRCh38/Sequence/WholeGenomeFasta/genome.fa) instead of the GATK Homo_sapiens_assembly38.fasta, whose 261 ALT, 525 HLA and 2,385 decoy contigs minimap2 does not handle as alternates. On a 30x real-data run with a no-ALT build that kept the hs38d1 decoys, removing the ALT contigs raised Clair3's germline calls in the ALT-contig footprint from 49,085 to 167,927 (MHC 4,280 to 28,899), with calls elsewhere within 0.1 %; the new default has no decoy contigs, so reads from decoy sequence now map to the primary assembly. The 195 contigs of the new FASTA are a subset of the GATK FASTA with identical names, lengths and MD5s, so the other GRCh38 resources are unchanged. Results differ from earlier versions in ALT regions, and -resume from an earlier version realigns every sample; pass the old path with --fasta to keep it (see docs/usage.md, GRCh38 reference) (@ljwharbers).
    • #258 - With --skip_m6a, a fiber-seq file whose reads carry no m6A calls now skips the fibertools-rs nucleosome, FIRE and QC steps (and SAMTOOLS_VIEW_FIBERPREP) with a warning naming the sample, and goes on to alignment as given, like a fiber = n row. METAEXTRACT emits the new m6a_calls ('true' when an MM tag of the first 1000 records has an A+a, T-a or ChEBI 28871 entry, 'false' when none has, 'unknown' when the records could not be read; only aux fields are decoded, so a CRAM needs no reference); 'unknown' keeps the fiber steps. On a 2 M-read PacBio fiber-seq slice without m6A these steps had reported zero m6A, nucleosomes and MSPs on every read and written a 98 GB FIRE copy of the 94 GB input. FIBERTOOLSRS_FIRE also replaces its per-read FIRE: no msp annotations on record; skipping warning (2 M lines, 214 MB of task logs on that slice) with one count line; all other output of ft fire is kept. A run resumed from an earlier version re-runs METAEXTRACT and FIBERTOOLSRS_FIRE (@ljwharbers).
    • #258 - LRSOMATICREPORT runs lrsomatic_report 2.1.0 (ghcr.io/ljwharbers/lrsomatic-report:2.1.0 / oras://ghcr.io/ljwharbers/lrsomatic-report-sif:2.1.0). Changes:
    • Severus whitelist-rescued SVs get their own hidden-by-default "rescued" tier, with a show/hide toggle in key findings, the SV table and the circos labels.
    • Failed (FAIL_*) SV records no longer count.
    • ClinVar is credited only to the gene that carries the coding or splice consequence.
    • Breakpoint and focal-deletion gene claims are checked by position.
    • Coding TMB counts unique variants and leads with SNVs.
    • ShatterSeek calls name their HC tiers, and there is a tier selector.
    • ReConPlot has a reason selector and caps the embedded per-chromosome figures at 12.
    • The phasing percentage is now of heterozygous variants.
    • Copy number 1 at high ploidy is called a "deep deletion".
    • The circos copy-number ring uses the overview's copy-number source.
    • Symbol-only gene lists get gene spans.
    • DeepSomatic genotypes are explained.
    • No absolute work-dir paths appear in the report.
    • The ASCAT tab says when ASCAT was skipped.
    • New optional inputs (--run-mode, Verdict status, ReConPlot focus figures) are wired below (@ljwharbers).
    • #243 - LRSOMATICREPORT now runs lrsomatic_report 2.0.0 (ghcr.io/ljwharbers/lrsomatic-report:2.0.0 / oras://ghcr.io/ljwharbers/lrsomatic-report-sif:2.0.0), which adds clinical-overview, genomic-instability (ShatterSeek, ecDNA), signature and ReConPlot sections and reads SAVANA and Padfoot. Wakhan's interactive HTML plots and heatmap are no longer staged or embedded; the report draws the top-ranked solution from integer_profile.bed, and the HTML plots stay in wakhan/. Each sample's report now waits for the run's last output of those tools, since several are optional per sample or ignored on failure, so there is no per-sample count to group on; this gives up the per-sample rendering of #200 for the report step (@ljwharbers).
    • #242 - Right-sized default resource requests from execution traces of ~30x ONT and PacBio runs (pairs and tumour-only, GRCh38 and CHM13), in a new withName section of conf/base.config. Lowered where requests were an order of magnitude above use: FIBERTOOLSRS_NUCLEOSOMES/FIRE/QC (200/144 GB -> 8 GB, 8-16 cpus; peaks <= 3.1 GB), FIBERTOOLSRS_PREDICTM6A (200 GB / 16 h -> 16 GB / 24 h at 24 cpus, for ~185 cpu-hours and a 7 GB peak), GERMLINE_VEP (16 cpus / 16 GB), SOMATIC_VEP/SV_VEP/VEP_SAVANA (24 / 144 GB -> 6 / 24 GB), the per-sample bcftools steps of the consensus, Verdict and phasing chains (6 / 36 GB -> 2 / 4 GB), LONGPHASE_MODCALL_* (12 -> 2 cpus, as it runs single-threaded; 64 GB), LRSOMATICREPORT (1 cpu / 32 GB), MOSDEPTH (4 / 8 GB), DeepVariant/DeepSomatic call_variants on CPU (144 -> 48 GB), and the labels of SIGPROFILER_MATRIXGENERATOR (process_single), CORAL_PLOT and AMPLICONCLASSIFIER (process_low). Raised where 30x data reaches the default: WAKHAN 36 -> 72 GB (38-64 GB on tumour-only samples), SEVERUS 36 -> 64 GB (32 GB on ONT pairs), SAVANA_RUN/SAVANA_TO 72 -> 96 GB, CRAMINO 2 -> 4 cpus. All keep attempt scaling. The fibertools tasks that request a GPU under --use_gpu keep their previous requests (24 cpus / 144 GB / 16 h), as that path was not measured. docs/usage.md now lists the measured needs of the heaviest steps at ~30x (@ljwharbers).
    • #250 - Resource defaults resized from 30x real-data runs: SAVANA_RUN 96 to 128 GB (paired peaks up to 118 GB), DEEPSOMATIC_MAKEEXAMPLES 144 to 192 GB (peak 120 GB), LRSOMATICREPORT 32 to 16 GB (peak 9 GB); BCFTOOLS_CALLER_CONSENSUS joins the small bcftools block (2 cpus / 4 GB, was 6 / 36 GB for under 1 GB), and the removed BCFTOOLS_ISEC, NORM_REJOIN, SORT_CONSENSUS and DS_VERDICT_*/DS_GERMLINE_REJOIN names leave its selector (@ljwharbers).
    • #258 - CLAIRS, DEEPSOMATIC_MAKEEXAMPLES, DEEPSOMATIC_CALLVARIANTS (CPU) and FIBERTOOLSRS_PREDICTM6A (CPU) request 48 cpus instead of 24; memory and time are unchanged. At 24 cpus paired DeepSomatic took 15.9 h of a 17.75 h 30x ONT pair run (make_examples 6.4 h, call_variants 8.5 h; 3.7 h and 5.4 h at 48), PacBio ClairS 6.2-6.4 h (3.6 h at 48) and m6A prediction 5.7-6.3 h at 97 % cpu efficiency (3.8 h at 64). DEEPSOMATIC_CALLVARIANTS under --use_gpu keeps 8 cpus (@ljwharbers).
