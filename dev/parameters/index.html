    --smallvar_filter_pass
    boolean    		 true Keep only PASS records from each small variant caller for downstream use.
    More info

    DeepVariant and DeepSomatic emit a record for every site they evaluate, so most records are RefCall (or GERMLINE/PON) rather than calls, and Clair3/ClairS keep their LowQual and NonSomatic calls. The per-caller VCFs published under `<outdir>/<sample>/variants/` are unaffected either way.

    boolean    		 - Also write gVCFs from DeepVariant and DeepSomatic, and publish them next to the VCFs.

    Modkit options

    Options for modkit pileup of base modifications

    ParameterDefaultDescription
    --modkit_args
    string    		 --cpg --modified-bases 5mC Command line arguments passed to `modkit pileup`. The value replaces the default rather than extending it; the default restricts the bedMethyl output to 5mC calls at CpG sites.
    More info

    Repeat `--cpg --modified-bases 5mC` when adding flags (e.g. `--cpg --modified-bases 5mC --combine-strands`). An empty value gives the unfiltered pileup of every modification code at every position: use `--modkit_args=''` (the `=` form) or an empty `modkit_args` entry in a params file, since `--modkit_args ''` reaches the pipeline as `true`. `--modified-bases` only filters the output: on PacBio data, positions where the 5mC and 5hmC probabilities sum above 1 are still dropped and non-conflicting 5hmC calls are counted in `N_other`. When `--modkit_phased` is set and DMR will run, `5hmC` is appended automatically if `--modified-bases` names `5mC` without it, and the published `modkit_pileup` files then include the 5hmC rows: `modkit dmr pair` rejects bedMethyl rows where an uncounted modification code (e.g. real dual 5mC/5hmC SUP calls) pushes `N_other` above zero. `--skip_dmr` keeps the value as given.
    --modkit_phased
    boolean    		 false Run `modkit pileup --phased` on the Longphase-haplotagged BAMs, producing `<sample>_hp1.bed.gz`, `<sample>_hp2.bed.gz` and `<sample>_combined.bed.gz`. The pileup then requires small-variant calling, phasing and haplotagging to have succeeded for the sample.

    ParameterDefaultDescription
    --minimap2_ont_model
    string    		 - Minimap ont model to use
    --minimap2_pb_model
    string    		 - Minimap Pacbio model to use
    --save_secondary_alignment
    boolean    		 true Whether to save secondary alignments
    --aligned_format
    string    		 cram File format of the aligned and haplotagged reads, in the work directory and in `bamfiles/`.
    Options: cram bam
    More info

    `cram` writes CRAM 3.0 with the reference embedded: 33-69 % smaller than BAM on long reads, readable without the FASTA, and decoded by every tool in the pipeline. `bam` writes BAM with `.bai` indexes, for downstream tools that cannot read CRAM.
    --skip_alignment
    boolean    		 false Use the input BAM/CRAM files as the alignment instead of realigning them with minimap2. Advanced; realigning is recommended.

    Every input file must be coordinate-sorted and aligned to `--fasta`: each `@SQ` contig must be in the FASTA with the same length, or the run stops. The pipeline still replaces the read groups, drops old phasing tags (`HP`, `PS`, `PQ`, `PC`) and, unless `--keep_kinetic_data` is set, the PacBio kinetics, drops secondary alignments when `--save_secondary_alignment` is false, and writes `--aligned_format`. Rows that fibertools-rs reads (Fiber-seq rows, and PacBio rows with kinetics while m6A is predicted) are not supported; add `--skip_fiber` / `--skip_m6a` to run them. See the usage documentation, section 'Skipping alignment'.

    Fibertools options

    ParameterDefaultDescription
    --autocorrelation
    boolean    		 false Pass --acf to fibertools qc to add nucleosome autocorrelation to the Fiber-seq QC output.
    --keep_kinetic_data
    boolean    		 false Keep the PacBio kinetics tags (fi, fp, ri, rp) on every read: passes --keep to fibertools predict-m6a and turns off any removal of kinetics at alignment.
    More info

    By default fibertools predict-m6a strips the kinetics from the reads it calls m6A on, and the alignment step removes them from every other PacBio read. This makes the aligned files considerably smaller. With this set, no step removes them. Keep them only if you need the raw kinetics downstream.

    boolean    		 false Pass --all-calls to fibertools predict-m6a to keep every m6A call regardless of its ML score, instead of only calls above its threshold.

    Severus options

    ParameterDefaultDescription
    --severus_minsupport
    integer    		 3 Minimum number of supporting reads for Severus to report an SV (Severus --min-support).
    --severus_whitelist
    string    		 - BED file of regions in which Severus reports every SV (Severus' --whitelist). Passed to Severus as --whitelist; its VCFs feed SV VEP, Wakhan and the report as usual. Not available under Conda.
    file-path
    More info

    Inside the whitelisted regions the patched build skips the read-quality, minimum-support and VNTR filters, and keeps single-read junctions only when a reciprocal or independently supported junction corroborates them. Use it for loci such as the IG and TCR genes, where translocations are often carried by few, divergent reads.
    --severus_whitelist_args
    string    		 - Extra arguments for the whitelist Severus run, e.g. `--whitelist-single-read any`, `--whitelist-allow-intra-region` or `--write-alignments`. Only used with `--severus_whitelist`.
    More info

    Appended after `--min-support <severus_minsupport> --output-read-ids`, so a later flag wins where Severus allows it. Ignored unless `--severus_whitelist` is set. `--whitelist-single-read` takes `reciprocal` (default), `any` or `off`; `--write-alignments` additionally publishes a `read_alignments` file.

    Savana options

    ParameterDefaultDescription
    --savana_pb_minsupport
    integer    		 10 Minimum supporting reads for SAVANA to call a variant on PacBio samples (--min_support with --pb). SAVANA's own testing found 10 outperforms its default of 5 on PacBio data.
    --savana_chromosomes
    string    		 - Restrict SAVANA's allele counting and binning to given chromosome numbers (SAVANA's -c/--chromosomes), e.g. '19'. Applies to both `savana cna` and `savana to`.
    More info

    Space-separated chromosome numbers, with 23 for chrX and 24 for chrY, e.g. `'1 4 23'`. Without it SAVANA already uses only chr1-22, chrX and chrY for copy number (chrM and alt, decoy and unplaced contigs are never binned), so this is only needed to narrow that further, as the test profiles do with `'19'`. SV calling is not affected; it is limited by the genome's contigs file.
    --savana_allele_min_reads
    integer    		 - Minimum reads per site for SAVANA to count a het-SNP allele (SAVANA's --allele_min_reads, default 10). Intended for test profiles running on downsampled data below that coverage floor.
    --savana_allele_mapq
    integer    		 - Mapping quality threshold for reads counted at a het-SNP site (SAVANA's --allele_mapq, default 5). Intended for test profiles running on downsampled data below that coverage floor.
    --savana_pb_pon_filter
    boolean    		 true Remove SAVANA SVs found in the germline SV panel of normals from PacBio tumour-only samples.
    More info

    SAVANA's PacBio classifier (`--pb`) only rejects a call on matched-normal evidence, so without a normal nearly every germline SV is reported as somatic (~28k on a 30x genome). The somatic VCF is then filtered against the genome's Severus panel of normals (`pon_file`) with Severus's matching rule, which removes ~97% of the calls. What remains is still mostly germline (on a PacBio sample with a matched normal, all 761 survivors were germline), so prefer Severus or a matched normal for PacBio tumour-only SVs. The unfiltered VCF is still published. Has no effect on ONT (SAVANA's tumour-only model) or paired samples, or on a genome without a `pon_file`.

    ReConPlot options

    Options for ReConPlot rearrangement/copy-number figures

    ParameterDefaultDescription
    --reconplot_genome
    string    		 - ReConPlot genome build for gene/chromosome annotations. Default: inferred from --genome (GRCh38 -> hg38, CHM13 -> T2T).
    Options: hg38 hg19 T2T mm10 mm39
    More info

    ReConPlot preset for chromosome lengths and gene annotations: `hg38`, `hg19`, `T2T`, `mm10` or `mm39`. Inferred from `--genome` (GRCh38 -> hg38, CHM13 -> T2T); a custom genome without a preset falls back to hg38 with a warning.
    --reconplot_max_cn
    integer    		 8 Copy number axis ceiling
    More info

    Upper limit of the copy-number axis in every ReConPlot figure; segments above it are drawn at the ceiling.
    --reconplot_min_svlen
    integer    		 0 Drop intra-chromosomal SVs shorter than this many bp (translocations are kept). 0 keeps everything.
    More info

    Intra-chromosomal SVs shorter than this many bp are left out of the figures and the harmonised SV table; translocations are always kept. 0 keeps every SV.
    --reconplot_max_svs
    integer    		 1000 Draw at most this many SVs in each ReConPlot figure set (per-chromosome, genome-wide, focus), the best supported first. 0 draws every SV.
    More info

    ReConPlot adds one plot layer per SV, so tens of thousands take hours and the genome-wide panel fails (R node stack overflow) from about 2,000 SVs. The limit applies separately to the per-chromosome figures (one budget shared by all chromosomes, since the cost is per SV drawn), the genome-wide strip and the focus panel; above it the SVs with the most tumour read support (then the longest) are drawn, and a figure missing some of its SVs says `top N of M SVs` in its title. The harmonised `*.reconplot_sv.tsv` table keeps every SV.
    --reconplot_exclude_vntr
    boolean    		 - Drop Severus SVs flagged as inside a VNTR
    More info

    When true, Severus SVs flagged as lying inside a VNTR are left out of the figures (Severus pairs only).
    --reconplot_regions
    string    		 - Comma-separated regions (e.g. 'chr8,chr17:30000000-50000000') for an additional multi-panel focus figure
    More info

    Comma-separated regions for an additional `focus/` figure per caller pair, each `chr` or `chr:start-end` (start < end), e.g. `chr8,chr17:30000000-50000000`. The syntax is checked at start-up; regions on contigs without copy-number data are skipped with a warning, and no focus figure is produced if none is left. Unset = no focus figure.
    --reconplot_genes
    string    		 - Comma-separated HUGO gene symbols to label on the focus figure
    More info
